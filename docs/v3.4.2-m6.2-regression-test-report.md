# Version 3.4.2 Milestone M6.2: Regression Test Report

## Areas checked after the CMS repair and pricing rollout

- **Homepage**: hero, "Why people choose Robayer WealthLab", the free-guide section, the "What we offer" grid, the featured eBook banner, the "Coming soon" grid, free resources, the founder section, and the newsletter signup form all rendered correctly on live production with no console errors. The featured banner's CTA correctly showed the regular price (GH₵49.00) with no active sale, and its underlying code path was changed this milestone to become sale-aware, so it was specifically checked rather than assumed unaffected.
- **Featured Book / Hero**: verified directly, see above.
- **Search / content filtering**: `js/components/content-filters.js` reads the same `data-topic`/`data-product-type`/`data-title` attributes on the redesigned book cards that it always has; the redesign only added new child markup and new attributes (`data-category`, star rating, price block), it did not remove or rename any attribute the filter code depends on.
- **Resources**: not modified this milestone; spot-checked as part of the general navigation pass, no errors observed.
- **Newsletter**: signup form present and rendering correctly on the homepage; not functionally re-tested end to end this pass, since no code in the newsletter path was touched this milestone.
- **Checkout**: see the Checkout Pricing Verification Report.
- **Customer Library**: the one concrete risk here, a product's downloadable file pointing at a soft-deleted media asset, was found live during this milestone's own testing and fixed; see the Media Library Repair Report. `PUT /api/admin/products/1/files` was confirmed returning 200 after the fix.
- **Reviews**: the book detail page's review section and the new star-rating display both correctly handle the current real state (zero approved reviews on product 1: no star rating shown on the card or hero, "No reviews yet" shown in the reviews section), which is the harder of the two states to get right (an empty state that could easily have rendered a broken "0 out of 5" or an empty `<span>` instead).
- **SEO**: the book detail page's `Offer.price` JSON-LD was found to be non-sale-aware and fixed this milestone; canonical URLs, meta descriptions, and the breadcrumb/FAQ structured data were not touched and were not observed to regress.
- **Dark Mode**: not pixel-verified with a full toggle walkthrough this pass. Every new CSS class added this milestone (`.price-block` and its children, `.countdown` and its children, `.star-rating` and its children, `.book-card__category`, `.book-card__author`) uses the site's existing semantic CSS custom properties (for example `var(--color-error)`, `var(--color-success)`, `var(--color-text-secondary)`) rather than hardcoded colors, which is the same mechanism every other theme-aware component on the site already relies on for correct dark-mode rendering.
- **Responsive Layout**: the book detail page was checked at a 375px mobile viewport on live production; the hero, price block, Buy Now/View My Library buttons, and the rest of the page laid out correctly with no horizontal overflow or broken elements.

## A significant process gap found and corrected during this milestone

Partway through Phase 6/7 verification, it was discovered that none of this milestone's static frontend changes (CSS, admin JS, admin HTML, the new countdown component, cache-busting version bumps) were actually live. The backend (Cloudflare Worker) is deployed independently via `wrangler deploy` and had been kept current throughout, but the static site is served by GitHub Pages directly from the `main` branch, and 170 files of local changes, spanning this milestone and some earlier ones, had never been committed or pushed. This meant every earlier "live" verification of the visual card/price-block/countdown work in this milestone had actually only confirmed correct HTML markup from the Worker-rendered book pages, not that the CSS to style it, or the admin JS to power it, had reached production.

This was surfaced to the user directly rather than silently pushed. With explicit approval, the relevant tracked-file changes were committed (100 files, the M6.2-relevant subset of the 170; a large, pre-existing pile of unrelated untracked planning documents from earlier in this project's history was deliberately left out of the commit as out of scope) and pushed to `origin/main`. All subsequent verification in this milestone's other five reports was performed after confirming, via GitHub Pages' actual served content, that the push had taken effect.

## A second incident during verification: reset-password email token corruption

Retrieving a real admin password-reset link via the connected email account produced a token with a character silently dropped by the email tool's own message decoding (confirmed reproducible and unrelated to the reset-password feature itself: the raw token was read directly from the `password_reset_tokens` table and matched the corrupted value with exactly one character restored at the exact position a MIME quoted-printable escape would explain). This was a tooling artifact in this session's environment, not a defect in `admin/reset-password/` or the reset-password API, which both worked correctly once given the correct token.

## Status

No functional regression was found in Homepage, Featured Book, Hero, Search, Resources, Customer Library (after the fix), Reviews, or Responsive Layout. Two real, separate SEO/pricing-consistency gaps (the book detail page's server-rendered card generator being stale relative to the client-side card renderer, and the JSON-LD `Offer.price` not being sale-aware) were found and fixed as part of this same regression pass rather than only being caught by a future review.
