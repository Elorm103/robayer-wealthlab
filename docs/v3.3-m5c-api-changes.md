# Version 3.3 Milestone M5C: API Changes

## New endpoints

### `POST /api/customer/reconcile-purchases`

Unauthenticated (no session exists yet — that is the point). Rate-limited 3/15min per IP. Body: `{ email: string }`. Always returns `{ success: true, data: { requested: true } }`, including under rate-limiting — no-enumeration, mirroring `POST /api/customer/auth/forgot-password` exactly. See `services/customer/reconciliationService.ts`.

### `GET /api/customer/review-reminders/opt-out?token={token}`

Unauthenticated, single-GET action (deliberately not the two-step GET-status/POST-confirm pattern `routes/unsubscribe.ts` uses — see that route's own header comment for why the simpler design is proportionate here). Rate-limited 20/min per IP. Returns a small server-rendered HTML confirmation page, not JSON — this is a link opened directly from an email, not an in-app `fetch()` call. Always the same confirmation message regardless of whether the token matched anything real.

### `GET /api/admin/analytics/activation-summary`

Authenticated (any admin role, read-only — same gating as every other `/api/admin/analytics/*` endpoint). Rate-limited 120/15min. Query params: `from`, `to` (same `parseRange()` validation as the existing summary/timeseries/top-products endpoints). Returns the eight new activation/reconciliation/conversion-funnel metrics — see the Analytics Architecture doc for the full list.

## Changed endpoints

### `POST /api/customer/auth/login`

New error code: `PASSWORD_NOT_SET` (HTTP 401), returned instead of the previous `INVALID_CREDENTIALS` when the account exists but has no password set yet. The message text was already distinct before this change ("This account hasn't set a password yet…") — this sprint only makes that distinction machine-readable via a dedicated `ApiErrorCode`, so the frontend can render a direct activation link rather than parsing message text. No new enumeration signal: the message already told the user this exact fact. Verified against the existing test suite (`tests/integration/rateLimiting*.test.ts`, `tests/integration/negative.test.ts`, `tests/integration/dashboardM3.test.ts`) to confirm none of their `INVALID_CREDENTIALS` assertions exercised the `password_not_set` path — none did.

### `GET /api/customer/auth/session`

Response now includes `isFirstSession: boolean` — `true` only for a customer's first-ever `customer_sessions` row (see `sessionService.ts`'s `countSessionsForCustomer()`). Purely additive; every existing consumer of this endpoint ignores the new field unchanged.

## Scheduled (non-HTTP)

### Cron Trigger, daily at 06:00 UTC

`worker/index.ts`'s new `scheduled()` handler calls `services/customer/reviewReminderService.ts`'s `sendDueReviewReminders()`. This project's first-ever Cron Trigger (`wrangler.jsonc`'s `triggers.crons`, previously absent). Not reachable via HTTP; no new public surface.
