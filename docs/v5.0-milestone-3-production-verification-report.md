## 4. Security verification

- **Admin-only content cannot be retrieved**: `answerCustomerQuestion()` hardcodes `visibility: 'public'` on every call to `searchKnowledge()` — this is not caller-configurable. Confirmed by attempting to inject `"visibility":"admin_only"` and `"actorType":"admin"` directly into the public `/ask` request body: both were silently ignored (the route only ever destructures `question`/`history`/`sessionId` from the body), and the model itself proactively declined to provide "internal admin content."
  - **Honest limitation**: production currently has **zero** admin-only documents indexed (all 39 indexed documents are `visibility='public'`, `data_classification='PRODUCTION'`), so this control has not been exercised against a real classified document in production. It is verified at the code level (the SQL filter in `searchService.ts` requires `r.visibility === visibility`) and via the Knowledge Base's own existing test suite, but not via a live red-team retrieval of real admin content, because none currently exists to retrieve.
- **Rate limiting functions correctly**: genuinely triggered in production during this verification pass — after roughly 15 `/ask` requests within a 5-minute window, the next request returned `{"success":false,"error":{"code":"RATE_LIMITED", ...}}`, matching the configured `15/5min` limit exactly.
- **Conversation history is session-scoped only**: confirmed via the actual deployed `customer_ai_messages` schema (`SELECT sql FROM sqlite_master WHERE name='customer_ai_messages'`) — no `customer_id` or any identity column exists anywhere in the table.
- **No persistent customer memory**: `session_id` is a client-generated UUID (`crypto.randomUUID()`, `js/components/ai-assistant.js`) stored in `sessionStorage`, cleared on tab close; "Reset conversation" rotates it and clears local history. Nothing about a visitor identity is ever transmitted to or stored by the backend.
