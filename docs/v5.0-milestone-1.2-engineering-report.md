# Version 5.0 Milestone 1.2 — AI Governance & Safety

**Engineering Report**

Status: Implementation, testing, and local verification complete. Migration application to remote D1 and production deployment are pending explicit founder confirmation (see the Production Verification Report).

Scope: closes every governance/security/compliance/operational gap this milestone's brief named, building directly on Milestone 1 (AI Gateway Foundation) and Milestone 1.1 (Operational Hardening). No new AI product, no new AI feature — `internal.gateway-diagnostic` remains the only registered feature.

---

## 1. New modules

| File | Responsibility |
|---|---|
| `services/ai/aiGatewayConfig.ts` | Single source of truth for budget config (per-request/daily/monthly/provider/platform) and retention config (storage mode/period), read directly from `site_settings`. Exists specifically so `services/ai/aiGateway.ts` never has to import `services/admin/` (which would create a circular dependency, since `settingsService.ts` already imports `services/ai/routingConfig.ts`). `settingsService.ts` now delegates its own reads here instead of maintaining a second, independent copy. |
| `services/ai/providerPolicy.ts` | The `AiSensitivityClassification` type (`PUBLIC`/`INTERNAL`/`CONFIDENTIAL`/`FINANCIAL`/`PERSONAL`/`HIGHLY_SENSITIVE`), validation, and the classification→approved-providers policy table. Deliberately code, not admin-editable `site_settings` — see its own header comment for why. |
| `services/ai/sensitiveDataMasking.ts` | Regex-based detection/redaction of API keys, bearer tokens, JWTs, labeled secrets, passwords, session ids, credentialed URLs, and payment-card-shaped digit runs. Applied only to what's about to be logged, never to the real outbound request. |
| `services/ai/promptEncryption.ts` | AES-256-GCM encryption/decryption via Web Crypto (`crypto.subtle`), the same native-Workers pattern already used by `utils/passwordHash.ts` (PBKDF2) and `utils/webhookSignature.ts` (HMAC). New optional secret: `AI_PROMPT_ENCRYPTION_KEY`. |
| `services/ai/retentionCleanupService.ts` | Scheduled cleanup — nulls out `prompt_text`/`response_text` (never the row) for entries past their `cleanup_eligible_date`, stamping `purged_at`. Runs from the existing single Cron Trigger. |

## 2. `services/ai/aiGateway.ts` — what changed

- `AiGatewayRequest.classification` is now **required**. An invalid/missing value throws `AiClassificationError` before routing is even resolved.
- New exported error classes: `AiClassificationError`, `AiPolicyViolationError`, `AiBudgetExceededError` — distinct types so a caller (or a route handler mapping to an `ApiErrorCode`) can tell "governance refused this on purpose" apart from "the provider failed."
- New exported `GATEWAY_VERSION` constant (`'1.2.0'`), recorded on every usage-log row.
- Per candidate, the order of checks is now: model support → provider policy (`providerPolicy.ts`) → preventive budget estimate (`estimateMaxCostUsdMicros()` + `checkBudget()`) → the actual provider call → the pre-existing post-call cost check (kept as a secondary safety net, not replaced).
- `maxCostUsdMicros` omitted by the caller now resolves to `aiGatewayConfig.ts`'s configured default, logged via `budget_decision`'s "(default cap inherited...)" suffix.
- Prompt/response text destined for `ai_usage_log` now passes through `prepareStorageFields()`: mask (`sensitiveDataMasking.ts`) → branch on the configured retention mode → optionally encrypt (`promptEncryption.ts`). This applies identically whether the call succeeded, failed, or was preventively rejected — a rejected call's prompt can still contain a secret worth masking.
- `logUsage()`'s `INSERT` grew from 17 to 26 bound columns (session id and prompt/response text already existed from Milestone 1.1; this milestone adds `sensitivity_classification`, `gateway_version`, `policy_version`, `provider_decision`, `budget_decision`, `retention_decision`, `masking_applied`, `cleanup_eligible_date`).

## 3. The one behavior change to the existing feature

`routes/admin/settings.ts`'s `handleAiGatewayTest()` now passes `classification: 'INTERNAL'` (mandatory) and no longer looks up/passes `maxCostUsdMicros` by hand — it relies on the Gateway's own default inheritance (Task 2). Functionally identical from the admin's perspective; the diagnostic test button behaves the same.

## 4. Reuse, not duplication (per the engineering rules)

- Budget/retention config reading lives in exactly one module (`aiGatewayConfig.ts`), imported by both the enforcement path (`aiGateway.ts`) and the display path (`settingsService.ts`) — fixing a real constant-drift bug caught during this milestone's own development (Milestone 1.1's `settingsService.ts` had independently defined `null` defaults for daily/monthly budgets; this milestone's new `aiGatewayConfig.ts` needed real numeric defaults for Task 2, and the two would have silently disagreed if not consolidated).
- Governance dashboard aggregates (classification/provider distribution, sensitive/masked counts, budget blocks, policy violations, cleanup status, oldest/newest stored prompt) live in `services/admin/aiUsageService.ts`'s new `getAiGovernanceSummary()` — the same file that already owned every other `ai_usage_log` aggregate query (Milestone 1.1's `getAiUsageAnalytics()`) — rather than a second, independent copy of similar SQL in `settingsService.ts`.
- The scheduled cleanup job reuses the existing single Cron Trigger and the existing `cron.heartbeat` audit pattern (`reviewReminderService`/`purchaseFollowupService`'s own `ctx.waitUntil()` + `recordAuditEvent()` shape) — no new trigger, no new heartbeat mechanism.
- Encryption and password hashing both use `crypto.subtle` — no new cryptography dependency.

## 5. Frontend

- Settings page's AI Gateway card renamed "AI Gateway — Governance Dashboard," gained: a budget-status badge, Policy Status, Retention Status (+ editable storage mode/retention period selects), a governance summary block (sensitive/masked prompt counts, budget blocks, policy violations, cleanup status, oldest/newest stored prompt), classification/provider distribution bar charts (reusing `window.AdminCharts.renderBarChart`, requiring `timeseries-chart.js` to now be included on this page), platform budget + per-provider budget inputs (one numeric field per known provider, not a raw JSON textarea).
- AI Usage page gained a Classification column, a classification filter dropdown, and a "Governance" section in the row-detail drawer (gateway/policy version, provider/budget/retention decisions, masking flag, cleanup eligibility, purge timestamp).
