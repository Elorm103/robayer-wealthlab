## Items considered and explicitly not amended

Per this ratification's own governing instruction ("do not assume every suggestion should be accepted"), the following ARB observations were reviewed and deliberately left as-is, not elevated to an amendment:

- **The coupon multi-account fraud vector (ARB Risk R6).** The ARB itself recommended accepting this risk explicitly rather than building mitigation now, consistent with this project's own already-established fraud-tooling deferral philosophy (`docs/v3-database-design.md`). Retained as an accepted, named risk in the Risk Register carried forward in the ratified Blueprint — not amended into the architecture as a control to build.
- **Future customer-facing API readiness (ARB Phase 6 finding).** The ARB itself judged this correctly out of scope until a real API consumer exists. No amendment made; noted as a future scoping trigger only.
- **Physically splitting `purchase_sessions` into a separate `orders` table now**, rather than the scheduled rename (AR-011). The ARB's own Decision 1 review explicitly recommended *against* this for Version 3.0.2, citing migration cost disproportionate to the naming benefit at current scale. Not amended.
