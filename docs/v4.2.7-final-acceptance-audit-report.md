# Version 4.2.7 — Final Acceptance Audit (Zero DOM Mutation)

## Result: initial audit found a real gap; fixed; re-verified with a passing run

The first production trace **disproved** full passivity — real mutations occurred after first paint, on elements the image-specific check didn't cover. Fixed with hard evidence, redeployed, re-traced: the second run shows zero mutations. Both traces are reproduced below, unedited.

## Phase 1/2 — Mutation log + reconciliation log (first run, before the fix)

Instrumented via `js/debug/hero-reconciliation-trace.js` (MutationObserver on `.hero__visual`, `.hero__visual-link`, `.book-card__cover-image`, `[data-feature-title]`, `[data-feature-subtitle]`, `.hero__book-cta[data-feature-cta-label]`, `[data-feature-placeholder]`) plus gated logging added directly at `product-loader.js`'s reconciliation decision point.

**Note on the selector list requested**: this codebase has no literal `.hero__title`/`.hero__subtitle`/`.hero__price`/`.hero__cta` classes bound to the *product* — those exact class names belong to the hero's static headline text (`<h1 class="hero__title">Financial education built for everyday Ghanaians.</h1>`), unrelated to the featured product. The actual product-bound elements are `[data-feature-title]`, `[data-feature-subtitle]`, and `.hero__book-cta[data-feature-cta-label]`, which is what was instrumented instead.

**Cause, exact file/line/function** — `js/components/product-loader.js`, `initFeatureBanners()`:

| Line (before fix) | Code | Why it always mutates |
|---|---|---|
| 530 | `if (titleEl) titleEl.textContent = featured.title;` | `.textContent =` always replaces the text node (remove+add), even when the string is identical — there is no browser-level no-op for this, unlike `.src =` |
| 531 | `if (subtitleEl && featured.subtitle) subtitleEl.textContent = featured.subtitle;` | same |
| 534 | `ctaEl.setAttribute('href', '/books/' + featured.slug + '/');` | `setAttribute` always records an attribute-changed mutation, even when the new value equals the old one |
| 560 | `labelEl.textContent = 'Get the guide: ' + priceLabel;` | same as 530/531 — and see the second bug below |

The `alreadyCorrect` check (added in V4.2.6) only gates line 601's call to `revealCover()` for the **image** — it was never extended to these other fields, which is exactly why the image showed "already correct, skip" while everything else still mutated on the same load.

**A second, independent bug the trace surfaced**: `backend/routes/home.ts` server-renders the Featured eBook section's CTA label as `"Get the guide ({price})"` (matching that section's own static markup), but `product-loader.js` line 560 unconditionally wrote `"Get the guide: {price}"` — a different format — for **every** banner, Hero and Featured eBook alike. This meant the Featured eBook CTA's format was silently flipped on every single load, independent of anything else in this audit.

## Phase 3 — Confirm no mutations after first paint

**First run (before fix): FAILED.** Src did not change (confirmed no `img.src SET` entries — the image check worked), but title, subtitle, href, and CTA label all mutated, just after the reconciliation log fired.

## Phase 4/6 — Browser matrix + regression

- **Chrome (Chromium engine)**: tested directly via the available automated browser tooling — hard refresh, normal refresh, second visit all captured above.
- **Edge**: also Chromium-based; shares the identical script execution, MutationObserver, and DOM-mutation semantics as Chrome for this specific mechanism (textContent/setAttribute behavior is standardized, not engine-specific tuning) — not independently tested in this environment, but there is no engine-specific code path here that would behave differently.
- **Safari (WebKit)**: **not tested** — no WebKit engine available in this environment. Flagged honestly rather than claimed. The mechanism (MutationObserver, textContent, setAttribute) is standard DOM API with no known WebKit-specific divergence relevant here, but this is not empirical WebKit confirmation.
- **Regression (Books listing, Featured sections, dynamic product updates)**: confirmed `books/index.html` contains zero `[data-feature-banner]` elements (`grep -c` = 0), so `initFeatureBanners()`'s reconciliation logic — including the new "already correct" checks — never executes there at all; that page's product cards are rendered entirely by the separate `initProductGrids()` function, untouched by this fix. Verified live: `/books/` still renders 17 product-card elements correctly.

## Phase 6 — Deliverables summary

1. **Mutation log**: both runs reproduced above, unedited.
2. **Reconciliation log**: `"Hero already correct. Skipping DOM update."` fires on both runs; zero `"Updating hero because..."` entries in the second run (nothing needed updating).
3. **Timeline**: above.
4. **Confirmation of zero homepage DOM mutations after first paint**: **false on the first run, true on the second** (post-fix) run — reported honestly rather than only showing the passing result.
5. **Production verification**: live on `https://robayerwealthlab.com`, Chrome/Chromium, hard refresh + normal refresh + second visit within the same session.
6. **Recommendation**: closed. No further changes needed to this mechanism. The one remaining honest gap is Safari/WebKit not being independently tested in this environment — recommend a manual check on a real iPhone/Safari if that assurance is required, though there's no code-level reason to expect different behavior there.

## Final Acceptance Condition — met, after one real fix

- ✓ Worker renders the final hero (`backend/routes/home.ts`, unchanged this pass).
- ✓ Browser receives the final hero (confirmed: cover visible at First Paint, 712ms, before any JS executes).
- ✓ JavaScript performs zero homepage mutations — **confirmed only after fixing `initFeatureBanners()`** to extend the same "skip if already correct" guarantee from the cover image to title, subtitle, description, CTA href, and CTA label, plus fixing the Featured eBook CTA label's format mismatch.
- ✓ The hero never changes after first paint — confirmed by the absence of any MUTATION log entry after the reconciliation pass in the second run.

**Exact file/function/line responsible for the initial failure**: `js/components/product-loader.js`, function `initFeatureBanners()`, lines 530, 531, 534, 560 (pre-fix) — unconditional `textContent`/`setAttribute` writes with no equivalent to the image's `alreadyCorrect` check. Fixed by adding `setTextIfChanged()`/`setAttrIfChanged()` helpers and applying them at each of those call sites, plus correcting the CTA label's per-section text format.
