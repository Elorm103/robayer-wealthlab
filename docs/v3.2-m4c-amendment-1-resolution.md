# Version 3.2 - Sprint M4C - Amendment 1 Resolution: Corrected Coupon Schema

**Required by:** M4B Architecture Readiness Assessment (`docs/v3.2-m4b-architecture-readiness-assessment.md`) - the coupon schema M4A cited as "ready to implement as-is" (`docs/v3-database-design.md`) references `platform_users`, a table that does not exist in the current production schema.

## Resolution

`backend/database/migrations/0020_reviews_and_coupons.sql` defines a corrected, platform-scope-only `coupons` table:

- **Removed**: `scope` column (`'platform' | 'creator'`), `creator_id` column, and the `CHECK (scope = 'platform' OR creator_id IS NOT NULL)` constraint - all meaningless for the current single-seller catalog.
- **Changed**: `created_by` now references `admin_users(id)` (the real, live admin-identity table) instead of the nonexistent `platform_users(id)`.
- **Preserved unchanged** from the original design: `code`, `discount_type`/`discount_value`, `max_redemptions`/`redemptions_count`, `first_purchase_only`, `starts_at`/`expires_at`, `status`, and the `coupon_redemptions` table's shape (including its `UNIQUE(purchase_session_id)` no-stacking constraint) - these parts of the original design were sound and did not depend on the unresolved `platform_users` question.
- **Added**: an optional `product_id INTEGER REFERENCES products(id)` on `coupons` (NULL = platform-wide) - a simpler replacement for the original design's product/creator scoping, using a table (`products`) that does exist today.

## Additional Correction (found during implementation, not anticipated by M4B)

The original `coupon_redemptions` design (per `v3-database-design.md`) did not include a `discount_pesewas` column. This migration adds one - the actual discount amount applied, snapshotted at redemption time, never recomputed later. Without it, there would be no way to audit how much discount a specific redemption actually granted (relevant given `coupons.discount_value` can change after a redemption already happened, e.g., an admin edits a coupon's percentage after some customers have already used it).

## Verification

Migration applied directly against local D1 (`wrangler d1 execute --file`) and confirmed via `sqlite_master` inspection: `product_reviews`, `coupons`, `coupon_redemptions` all created successfully; `purchase_sessions.coupon_id`/`discount_pesewas` columns confirmed present via the table's own `CREATE TABLE` SQL. `backend/database/schema.sql` updated to match (the cumulative reference document this project maintains alongside migrations, per `v3.0.2-m2-database-changes.md`'s own established precedent).

**Status: Resolved.**
