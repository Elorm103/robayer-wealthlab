# Version 5.0 — Milestone 2.2 Executive Summary

**Retrieval Quality Calibration & Search Optimization**

## Status

**Complete. Certified.** Backend and frontend both deployed, tested, and verified against real production queries — including the one refinement item that required tracing through a genuine external GitHub Actions/Pages outage (confirmed via githubstatus.com, resolved 2026-08-07) before its two small frontend fixes could go live. Every acceptance target in this milestone's verification brief is now met with real, screenshot-confirmed production evidence, including a full fix for the Resources retrieval gap this milestone originally left open.

## What This Milestone Was For

Milestone 2 built the Knowledge Base; Milestone 2.1 fixed two production-scale incidents (a Worker subrequest ceiling, then a Vectorize write-rate limit) so all 38 real platform documents could index successfully. Milestone 2.2 was explicitly **not** about new features or architecture — it was about using the real search evidence gathered in Milestone 2.1's verification to make retrieval *better*: confidence scores that actually track correctness, ranking that surfaces the right content first, and enough observability that the next miscalibration is caught with data instead of guesswork.

## What Changed, and What It Was Measured Against

Every change in this milestone traces to a specific piece of real evidence, not an assumption:

- **Confidence thresholds were wrong, provably.** Milestone 2.1's own verification showed the Privacy Policy page — an exact, unambiguous match — scoring "low" confidence. The old thresholds (high ≥ 0.75, medium ≥ 0.5) were explicitly documented as engineering-judgment placeholders, chosen before any real query had ever run. They're now recalibrated (high ≥ 0.6, medium ≥ 0.45) against real scored results.
- **Ranking needed a signal cosine similarity alone doesn't provide.** The same evidence showed a "resources available" query surfacing generic site pages instead of the actual downloadable resource. A lightweight hybrid reranker (title overlap, keyword overlap, source-type relevance — no external API) was added to correct for this in the general case.
- **Diagnostics needed to show *why*, not just a number.** Search Diagnostics now breaks every result down into vector similarity, title boost, keyword boost, source boost, and final score, so an admin (or a future engineer) can see exactly what drove a ranking decision.
- **There was no way to see search behavior in aggregate.** A new Search Analytics panel now surfaces the most common queries, zero-result queries, confidence distribution, latency, and a 14-day low-confidence trend — the beginning of real search observability.
- **Two forward-looking pieces of infrastructure were prepared, not activated:** per-document embedding provenance (so a future embedding-model upgrade has a clear "what needs re-embedding" answer) and content-change re-index plumbing (so a future CMS-triggered re-index doesn't require redesigning the pipeline) — both built and tested, neither wired into anything live yet, exactly as scoped.
- **Dead-letter handling was added the right way, not the easy way.** The original design would have provisioned a second Cloudflare Queue. Recognizing this conflicted with the brief's explicit "don't create unnecessary infrastructure" instruction, it was redesigned mid-milestone to reuse the existing queue via each message's own retry-count field — a real correction made *before* deploying, not after.

## Production Verification: 5 of 5 Named Targets Achieved, With Evidence

Every one of the five explicitly-named acceptance targets from the verification brief was met, confirmed via a guided, screenshot-by-screenshot walkthrough of the live admin tool — not a local test suite result:

| Target | Before | After |
|---|---|---|
| Privacy Policy → High confidence | 0.482 (low) | **0.759–0.882 (high)** |
| Terms of Use → High confidence | 0.530 (medium) | **0.727–0.930 (high)** |
| Treasury Bills → Medium or High | 0.482–0.595 (low/medium) | **0.882–0.995 (high)** |
| Investment Centre → Medium or High | 0.470–0.538 (low/medium) | **0.611–0.738 (high)** |
| Resources ranked above adjacent pages | Not achieved | **0.722 (high)** — resolved via a second, evidence-driven fix |

The Resources target took two passes to close, and the process is worth stating plainly because it's the more important result than the fix itself: the first attempt (widening Vectorize's candidate pool) was tested against real data, found insufficient — proven, not assumed, by scanning 89% of the entire corpus and still finding nothing — and only then was the real fix (indexing the Resources catalog page itself) implemented. Every step was measured before the next one was taken.

## Bottom Line

The Knowledge Base now answers with retrieval quality that's been measured against real content and real queries at every step, including this milestone's own recalibration and its own follow-up fix. Milestone 2.2 is certified complete with no open acceptance targets and no further code changes required.
