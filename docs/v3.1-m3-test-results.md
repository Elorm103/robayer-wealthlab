## Manual / browser verification (not covered by the automated suite)

UI feature correctness is outside what `@cloudflare/vitest-pool-workers`
exercises, so every new page and interactive flow was additionally
verified against a real `wrangler dev` instance and a separately-seeded
local D1, using real HTTP requests and real cookies (not mocked):

- All 5 dashboard pages (My Library, Purchase History, Receipts,
  Licenses, Account Security) load and render correctly for an
  authenticated customer.
- Unauthenticated access to any dashboard page correctly redirects to
  `/checkout/sign-in/?redirect=<original-path>`.
- Sign-in correctly honors a valid `?redirect=` target and falls back
  to `/dashboard/` for a missing or invalid one.
- Download mint-then-redirect produces a real, observed network
  request and file response.
- Change-password: verified both the success path (session stays
  alive, other sessions revoked, sessions list re-fetches) and the
  failure path (wrong current password shows an inline error, no
  session is revoked).
- Session revoke: verified both the cancel path (`window.confirm()`
  declined -> zero network calls, list unchanged) and the confirm path
  (real API call, list refreshes, revoked session disappears) - the
  AR-009 confirmation requirement was checked functionally, not just
  for markup presence.
- Responsive: mobile viewport (375x812) shows zero horizontal overflow
  and full nav/card functionality on My Library.
- Dark mode: verified across nav, cards, and badges; this pass is what
  surfaced and led to the fix of the one real accessibility defect
  found in M3B (see Known Limitations / Implementation Report).

## Additional manual verification performed at M3C (Acceptance Review)

- **Tablet viewport (768x1024)** - not checked at M3B, performed at
  M3C: zero horizontal overflow, dashboard nav links wrap correctly.
- **Keyboard-only navigation** - explicitly required by the M3A Testing
  Strategy, not performed at M3B, performed at M3C: tabbed from the
  skip-link through the header, dashboard nav, and into page content
  (the Download button), confirming a real, visible focus ring at every
  stop and correct `aria-current="page"` tab-order behavior.
- **Session self-revocation, live** - a direct `curl` call (bypassing
  the dashboard UI) confirmed the defect described in Known Limitations
  before the fix, and confirmed the fix afterward: the same call now
  correctly returns `CANNOT_REVOKE_CURRENT_SESSION` and the session
  remains valid; a genuinely different session still revokes normally.

Every verification claim above is backed by an observed network
request, DOM state check, or computed-style read - none is asserted
