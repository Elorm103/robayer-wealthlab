## 1. Pre-Deployment State

`wrangler d1 migrations list robayer-wealthlab-db --remote` was checked before touching anything: the production tracking table correctly showed migrations 0001-0019 already applied (from M1/M2/M3's own prior deployments) with exactly one pending migration, `0020_reviews_and_coupons.sql` - confirming production's own migration bookkeeping is healthy and in sync (unlike the long-standing local-development-only tracking mismatch documented throughout this project's history, which does not affect the remote database at all).

## 2. Database Migration

```
wrangler d1 migrations apply robayer-wealthlab-db --remote
```

Applied successfully: **13 SQL commands executed in 5.79ms**, migration `0020_reviews_and_coupons.sql` marked `✅`.

**Verified directly against the live production schema afterward** (not merely trusted from the apply command's own success message):
- `SELECT name FROM sqlite_master WHERE type='table' AND name IN ('product_reviews','coupons','coupon_redemptions')` returned all three table names.
- `SELECT sql FROM sqlite_master WHERE type='table' AND name='purchase_sessions'` confirmed the table definition includes `coupon_id INTEGER REFERENCES coupons(id), discount_pesewas INTEGER NOT NULL DEFAULT 0 CHECK (discount_pesewas >= 0)`.

No existing table, column, or row was altered - confirmed by the migration's own purely-additive design (see `v3.2-m4c-database-changes.md`) and independently re-confirmed by this direct post-apply schema inspection.
