## Cache Considerations

- `/books/*` responses (including the new Reviews section and coupon-input markup) are served with `Cache-Control: no-store`, unchanged by M4 - confirmed via `routes/books.ts`'s existing `htmlResponse()` helper, which every M4-touched response still passes through. No caching behavior change, no risk of a stale pre-M4 page being served after deployment.
- New API endpoints (`/api/products/:slug/reviews`, `/api/coupons/validate`, all `/api/admin/*` and `/api/customer/*` additions) follow this codebase's existing convention of no explicit cache headers on dynamic JSON API responses - consistent with every other API endpoint in this project, not a new consideration M4 introduces.
- Static admin pages and JS files are served from GitHub Pages, subject to that platform's own default caching - identical to every other static asset already on the site; no M4-specific cache-busting concern beyond what already applies to `js/components/buy-button.js`'s own modification (a returning visitor's browser cache may briefly serve the pre-M4 version of that file until its own cache expires - the same, already-accepted behavior every prior milestone's static-file edits have had).
