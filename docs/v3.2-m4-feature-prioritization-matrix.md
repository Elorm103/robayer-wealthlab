# Version 3.2 - Sprint M4A - M4 Feature Prioritization Matrix

Every candidate feature named in the sprint brief, evaluated on Business Value, Engineering Effort, Risk, Dependencies, and Recommended Milestone. Effort scale: **S** (< 1 sprint-equivalent), **M** (roughly one milestone), **L** (multiple milestones or a dedicated architecture pass first), **XL** (a new product line).

## Recommended Additions (features not in the original candidate list)

- **Purchase-triggered review-request email** - the natural trigger mechanism for the Reviews feature above; small enough to fold directly into M4/M5 rather than treat as separate.
- **A lightweight "course interest" signal-gathering feature for M6** (e.g., a single "Notify me about courses" opt-in on relevant product pages, tracked in a trivially small table) - not a course platform, a demand-measurement instrument. This directly answers the open question ("does real demand exist?") the Course Platform row above is gated on, at a fraction of the cost, before committing to the XL investment.
- **Admin-panel test coverage for whichever surface M4 touches** (reviews moderation, coupon management) - not a customer-facing feature, but this review's own Technical Debt Review names it as the one item that should ride along with M4 regardless of final scope, to avoid repeating the exact "self-imposed Testing Strategy gap caught only by external review" pattern this project has now seen twice.

## A Note on Business-Value Scoring

"Business value" throughout this matrix is scored relative to this platform's *current* stage (one flagship product, few real customers, mature commerce core, zero trust/retention mechanics) - not relative to a hypothetical mature multi-course platform. This is why Reviews and Coupons score higher than Course Platform despite Course Platform being the larger long-term opportunity: value here means "value obtainable soon, with reasonable confidence, given where the platform actually is today."
