# Version 5.0 — Knowledge Base Changelog: Milestone 2 → Milestone 2.2

## Milestone 2 (Knowledge Base — initial build)

- Vectorize index (`robayer-knowledge-base`), migration `0036` (`knowledge_documents`, `knowledge_chunks`, `knowledge_faqs`, `knowledge_indexing_runs`, `knowledge_search_log`).
- Document readers for blog posts, resources, products (live-page fetch), static pages (sitemap crawl), CMS settings.
- Chunking, HTML/JSON-LD extraction, embedding via the AI Gateway's `embedText()`.
- Synchronous, single-invocation indexing orchestrator.
- Basic `searchKnowledge()` — cosine similarity only, fixed 0.75/0.5 confidence thresholds (explicitly documented as unvalidated placeholders).
- Admin dashboard: Index Health, Documents table, Search Diagnostics (single score, no breakdown), Indexing Run History.
- All 38 real platform documents indexed for the first time.

## Milestone 2.1 (production scale fixes)

- **Incident 1:** Worker subrequest limit exceeded on full rebuilds. Fixed by splitting indexing into a planning phase + Cloudflare Queue consumer (migration `0037` adds `documents_enqueued`/`documents_resolved`).
- **Incident 2:** Vectorize write-rate limit (`40014`) on concurrent consumer invocations. Fixed by batching all of a consumer batch's vectors into one `upsert()` call, capping `max_concurrency: 2`, and adding bounded retry-with-backoff for genuine rate-limit errors.
- **Incident 3:** `searchKnowledge()`'s `returnMetadata: false` was invalid on current (V2) Vectorize indexes (`40026`) — fixed to `'none'`; test double hardened to catch this class of bug in the future.
- Result: 38/38 documents indexed, 0 failed, 0 pending, verified live.
- Phase 3 retrieval verification (7 real queries) surfaced the confidence-miscalibration and Resources-ranking issues Milestone 2.2 was built to address.

## Milestone 2.2 (this milestone — retrieval quality)

### Added
- `services/knowledge/ranking.ts` — hybrid reranking (title/keyword/source-type boosts) and recalibrated confidence thresholds.
- `services/admin/knowledgeSearchAnalyticsService.ts` — search analytics aggregation (most common/zero-result searches, confidence distribution, most-retrieved documents, success rate, latency, 14-day low-confidence trend).
- `enqueueContentChangeReindex()` — content-change re-index infrastructure, built and tested, not wired into any CMS route yet.
- Dead-letter tracking (`knowledge_indexing_dead_letters` table, `recordDeadLetters()`/`retryDeadLetter()`), reusing the existing queue rather than provisioning a second one.
- Embedding version/provenance tracking on `knowledge_documents`.
- Migration `0038` (all of the above schema additions).
- Search Diagnostics UI: full score breakdown per result (vector similarity, each boost, final score).
- Search Analytics, Embedding Versions, and Dead Letters panels on the admin dashboard.

### Changed
- `searchKnowledge()` now sorts and confidence-buckets by the blended (post-reranking) score, not raw cosine similarity.
- Confidence thresholds: `high ≥ 0.75, medium ≥ 0.5` → `high ≥ 0.6, medium ≥ 0.45`.
- `knowledge_search_log` gains `top_document_id`.

### Fixed (mid-milestone, before certification)
- Reconsidered and replaced a second-Cloudflare-Queue dead-letter design with a reused-existing-queue design after recognizing it conflicted with the brief's own "don't create unnecessary infrastructure" instruction.

### Fixed (post-certification refinement pass)
- Search Diagnostics widened to request up to 20 results (`topK` 80, was 20) to measure the Resources retrieval gap — deployed and confirmed live; proved oversampling alone was insufficient (89% of the corpus scanned, resource item still not found).
- Search Analytics panel now refreshes after each new Search Diagnostics query instead of only on page load — deployed and confirmed live via real, incrementing search counts.
- `getStaticPageDocuments()` no longer excludes the `/resources/` catalog page — it's now indexed as a first-class `static_page` document, resolving the Resources ranking gap for real (0.722, high confidence, confirmed via a live incremental reindex and re-query).
- (Along the way) diagnosed and worked around a genuine external GitHub Actions/Pages platform outage that delayed the first two frontend fixes — fully documented in the Deployment Guide, resolved once GitHub's own infrastructure recovered.

### Verified in production
- **5 of 5** explicitly-named acceptance targets achieved (Privacy Policy, Terms of Use, Treasury Bills, Investment Centre, Resources) with real, screenshot-confirmed evidence — all 7 representative queries fully pass.

### Explicitly not done (by design, per brief)
- No architecture redesign — same Queue, same Vectorize index, same AI Gateway.
- No new Cloudflare infrastructure beyond the one migration.
- No Customer AI work.
