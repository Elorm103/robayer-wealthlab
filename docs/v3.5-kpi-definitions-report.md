# Version 3.5: KPI Definitions Report

Every KPI shown on the executive dashboard, its exact SQL-level definition, and the table(s) it comes from. Amounts are pesewas internally (GHS smallest unit) and rendered in GH₵ on the page. "Verified" always means `purchase_sessions.status = 'verified'` — the one real revenue ledger this project has (see `docs/payment-verification.md`).

## Revenue & orders

| KPI | Definition |
|---|---|
| Today's revenue | `SUM(amount_pesewas)` where `verified_at` falls on the current UTC date |
| Yesterday's revenue | Same, for the prior UTC date |
| This month's revenue | Same, from the 1st of the current UTC month to now |
| Lifetime revenue | Same, no date bound |
| Orders today / this month | `COUNT(*)` of verified purchase_sessions in the same windows as above |
| Completed orders | `COUNT(*)` of all verified purchase_sessions, lifetime |
| Pending orders | `COUNT(*)` where `status = 'pending'` and `expires_at` has not yet passed (an expired-but-never-resolved session is not "pending," it is abandoned) |
| Refunds | `COUNT(*)` where `status = 'refunded'` |
| Conversion rate | Verified purchases ÷ all purchase_sessions created, over the trailing 30 days. Shown as "No data yet" if zero checkouts were started in that window (never divides by zero) |
| Returning customers | Count of distinct `customer_id` values with 2 or more lifetime verified purchases |
| Average order value | Lifetime revenue ÷ lifetime completed order count |

## Content & growth

| KPI | Definition |
|---|---|
| Newsletter subscribers | `COUNT(*)` from `newsletter_subscribers` where `status = 'subscribed'` |
| New subscribers today | Same, further filtered to `subscribed_at` on the current UTC date |
| Published books | `COUNT(*)` from `products` where `status = 'active'` |
| Published resources | `COUNT(*)` from `resources` where `status = 'published'` |
| Published blog posts | `COUNT(*)` from `blog_posts` where `status = 'published'` |
| Published reviews | `COUNT(*)` from `product_reviews` where `status = 'approved'` |
| Average rating | `AVG(rating)` over the same approved-review set; "No reviews yet" if none exist |
| Active coupons | `COUNT(*)` from `coupons` where `status = 'active'` and (no expiry, or expiry in the future) |
| Expired coupons | `COUNT(*)` where `status = 'expired'`, or `expires_at` has already passed regardless of stored status (a coupon whose expiry silently passed without anyone flipping its status is still, honestly, expired) |
| Draft content | Sum of draft `products` + draft `resources` + draft `blog_posts` |

## Publishing inventory

| KPI | Definition |
|---|---|
| Books / Resources / Blog (published, draft, coming-soon, archived) | `COUNT(*)` grouped by each table's own `status` column |
| Media assets | `COUNT(*)` from `media_assets` where not soft-deleted |
| Broken media references | Count of products/blog posts/resources whose cover/thumbnail/preview/OG/file media id is non-null but does not resolve to a real, non-deleted `media_assets` row — the exact defect class Version 3.4.2's Media Library repair fixed one live instance of |
| Products missing covers | Active products with `cover_media_id IS NULL`. **Scoped to `active` only, not `coming-soon`** — a real, live coming-soon product in this catalog intentionally has no cover yet (see `services/productService.ts`'s own validation, which uses the identical scope), and its card already degrades gracefully with no image |
| Products missing metadata | Active products missing `author` or `short_description` |
| Products missing SEO | Active products missing `seo_title` or `seo_description` |
