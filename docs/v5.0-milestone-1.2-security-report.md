# Version 5.0 Milestone 1.2 — AI Governance & Safety

**Security Report**

Per the founder's explicit Task 9 instruction: "Be brutally honest." Every finding below was verified directly against the code in this milestone, not assumed.

---

## 1. No secrets leak

**Confirmed.** `env.OPENAI_API_KEY` is read in exactly one place (`openAiProvider.ts`'s `Authorization` header). `env.AI_PROMPT_ENCRYPTION_KEY` (new this milestone) is read in exactly one place (`promptEncryption.ts`'s `importKey()`), only ever passed to `crypto.subtle.importKey()`, never logged, never returned in any API response, never written to `ai_usage_log`. Both secret-configured states are surfaced only as booleans (`openAiConfigured`, `retentionStatus.encryptionAvailable`) — never their values.

**New this milestone, and the one place this needed real care:** prompt/response text is now optionally stored, encrypted. The encryption key itself never touches `ai_usage_log` — only ciphertext (`enc:v1:<iv>:<data>`) does. Verified: `tests/unit/promptEncryption.test.ts`'s "encrypts to a value carrying the enc:v1: marker... does not contain plaintext" case, and `aiGateway.test.ts`'s encrypted-storage test asserts `prompt_text` does not contain the original text.

**One honest gap carried forward from Milestone 1.1, unchanged:** `AiProvider.estimateCostUsdMicros`/error-message construction is a per-provider discipline (`openAiProvider.ts` builds error messages only from the provider's own response body), not something the Gateway structurally enforces. A carelessly written second provider *could* accidentally echo a request header into an error message. This remains a code-review responsibility, not a runtime guarantee.

## 2. No provider bypass exists

**Confirmed, and now enforced at TWO layers, not one.** As before Milestone 1.2: no module besides `providerRegistry.ts` imports `services/ai/providers/*`, so this remains the only door architecturally. NEW this milestone: even within that one door, `services/ai/providerPolicy.ts`'s `isProviderApprovedForClassification()` check runs before every candidate is contacted — a routing-table entry naming an unapproved provider for a call's classification is skipped, never reached, regardless of what `routingConfig.ts` says. Verified: `tests/unit/providerPolicy.test.ts`'s default-deny test.

**Honest limitation:** today's `PROVIDER_POLICY` table approves `openai` for every one of the six classifications. This is not because each classification's data-handling risk with OpenAI has been individually assessed — it's because OpenAI is the only provider this project has ever integrated, and there's nothing to compare it against yet. The mechanism is real and enforced; the actual policy content is a placeholder pending a real second-provider decision (see the Governance Report's "Founder Principle" section).

## 3. No prompt bypass exists

**Confirmed for the one existing feature.** `internal.gateway-diagnostic` (the only registered feature) resolves its prompt via `ai_prompts` (`promptKey`), never inline text in the calling route since this milestone (see the Engineering Report). Every `callAi()` invocation goes through the same masking → retention-mode branch (`prepareStorageFields()`), with no code path that skips it — masking is computed unconditionally, before the storage-mode check, not after.

**What "prompt bypass" does NOT mean here:** it does not mean prompt-injection-proof. See §9 below (unchanged from Milestone 1.1's own honest framing): the defense against prompt injection is structural (no tool-calling capability, response is never parsed as commands), not a content filter. This remains untested against a real feature that accepts untrusted user input, because none exists yet.

## 4. No logging bypass exists

**Confirmed.** Every exit path out of `callAi()` — success, provider error, preventive budget rejection, preventive policy rejection, post-call budget rejection, model-unsupported — calls `logUsage()` before returning or throwing. The one exception, unchanged from Milestone 1.1: an invalid `classification` or an unregistered `feature` throws before any routing/DB work happens at all, so there is genuinely nothing to log yet (no provider was even resolved) — this is a documented, deliberate design choice, not an oversight. Verified: `aiGateway.test.ts`'s "throws AiClassificationError immediately... with no usage row written" and "throws immediately for an unregistered feature key... no usage row written."

**`logUsage()` itself never throws** — a DB write failure is caught and logged via `logger.error()`, never propagated to break the caller. This is unchanged from Milestone 1 and remains correct: a logging failure must not additionally break an AI feature that otherwise succeeded or failed cleanly.

## 5. No cost bypass exists

**Substantially improved, with one honest, structural limitation that cannot be fully closed without streaming.**

- **Preventive, not just post-hoc, as of this milestone (Task 1).** A candidate's estimated maximum cost is checked against the per-request cap, daily budget, monthly budget, provider lifetime budget, and platform lifetime budget — in that order — BEFORE the provider is ever contacted. Verified: `aiGateway.test.ts`'s "preventively refuses an over-cap call BEFORE contacting the provider — zero real spend, provider never called" (asserts `tokens_in`/`tokens_out`/`cost_usd_micros` are all 0, i.e. the queued mock response was never consumed) and "preventively refuses a call once the configured daily budget would be exceeded."
- **Mandatory default (Task 2).** `maxCostUsdMicros` omitted by a caller now inherits the platform-configured default automatically — there is no code path left where a call runs with literally zero cost ceiling. Verified: `aiGateway.test.ts`'s "inherits the platform-configured default cost cap."
- **The one real, unclosed gap:** the pre-call estimate is a heuristic (`estimateInputTokens()`: ~4 characters per token, deliberately rounded up to bias toward over-estimating). If a real prompt tokenizes far more densely than that heuristic predicts, the pre-call check can pass while the actual reported cost exceeds the cap — this is what the post-call safety net (unchanged from Milestone 1.1, still present) exists to catch, and by the time it fires, the provider has already been billed for that one call. This is a structural property of any non-streaming, pay-per-response-token API, not a bug in this implementation. Verified directly: `aiGateway.test.ts`'s "post-call safety net catches a real cost that the pre-call estimate under-predicted" deliberately constructs this exact scenario and confirms the post-call path fires and records real (nonzero) token/cost figures, distinct from the zero-cost preventive-rejection path.
- **Daily/monthly/provider/platform budgets now genuinely block**, reversing Milestone 1.1's explicit "warning-only" decision — this is a deliberate, founder-requested behavior change (Task 1 explicitly asked for blocking), not a silent reversal. See the Governance Report for the full before/after.

## 6. No RBAC bypass exists

**Confirmed, unchanged in mechanism from Milestone 1.1.** Every AI Gateway/AI Usage route still requires `super_admin` via `requireRole(['super_admin'])`. No new route was added this milestone that departs from that posture. The Settings page's new governance fields (policy status, retention status, budget status, etc.) ride the same `GET /api/admin/settings/status` endpoint, already `super_admin`-gated.

## 7. No CSRF regression

**Confirmed.** The one mutating AI endpoint (`POST /api/admin/settings/ai-gateway/test`) keeps `requireCsrf`, unchanged. No new mutating AI endpoint was added this milestone — the new governance settings (budgets, retention policy) are written through the existing `PATCH /api/admin/settings` endpoint, which already had `requireCsrf`.

## 8. No audit gaps

**Substantially closed, per Task 8.** Every `ai_usage_log` row now carries: `gateway_version`, `policy_version`, `sensitivity_classification`, `provider_decision`, `budget_decision`, `retention_decision`, `masking_applied`, `cleanup_eligible_date`, `purged_at` — in addition to everything Milestone 1.1 already recorded (session id, prompt/response when stored, tokens, cost, latency, fallback flag). All are plain-text/integer columns, searchable via the existing `search` filter in `aiUsageService.ts` (extended this milestone to also match `provider_decision`/`budget_decision`/`retention_decision`).

**One honest gap:** there is still no separate, append-only "governance decision log" distinct from `ai_usage_log` itself — a budget/policy rejection is recorded as a row in the SAME table a successful call would use (with zero cost, `succeeded = 0`). This is a deliberate reuse of one existing, already-audited mechanism rather than a second one (per the engineering rules' "do not duplicate logic"), but it does mean a rejection and a real provider failure share a table, distinguishable only by `provider_decision`/`budget_decision` text, not a dedicated event type. Acceptable at today's scale; worth a dedicated `ai_governance_events` table if this volume grows large enough that filtering by decision-text substrings becomes slow or unwieldy.

## 9. Prompt injection (carried forward from Milestone 1.1, re-verified, unchanged)

The model has no tool-calling/function-calling capability (`openAiProvider.ts`'s request body: `{model, messages, max_tokens, temperature}` only). The only caller (`handleAiGatewayTest`) treats the response as opaque display text. This remains the structural defense against injection-as-privilege-escalation described in `docs/v5.0-security-architecture.md` — verified still true after this milestone's changes (no new tool/function surface was added).

## Summary

Of the seven items the founder asked to verify, six are cleanly confirmed with test evidence. The seventh (cost bypass) is **substantially, not absolutely, closed** — preventive enforcement now exists and is real, but a non-streaming API's fundamental "you're billed the moment the provider responds" property means a heuristic-driven pre-call estimate can never be a perfect guarantee. This is disclosed here plainly rather than glossed over, and is the single most important honest caveat in this report.
