# Version 3.3 Sprint M5A: Feature Inventory

Independently checks every candidate feature named in the sprint brief, plus additional candidates this review's own evidence-gathering surfaced, against the actual codebase (not assumption). Several candidates already exist in some form; presenting them as net-new would misrepresent the platform's real state, exactly the kind of error this project's own governance history (Milestone M4B's independent review of Milestone M4A) has caught and corrected before.

---

## Already Exists (Confirmed by Direct Inspection)

| Candidate | Actual State |
|---|---|
| Newsletter system | Fully built (Version 2.1, Milestone Phase 6): campaign creation, recipient rostering, unsubscribe tokens, admin recipient caps. Never yet used for a real campaign. |
| Related products | Fully built (`product-loader.js`'s `getRelatedProducts`, rendered on every product page). Topic and type-based, not personalized. |
| Analytics dashboard | Partially exists: an admin-facing business analytics dashboard (Version 2.0, revenue, order trends, top products) is fully built. Visitor and marketing analytics (traffic, funnel, acquisition source) does not exist at all. |
| SEO improvements | Already reasonably mature: JSON-LD structured data (including the aggregate rating schema added in Milestone M4), meta tags, canonical URLs, breadcrumb schema, all confirmed present on the product detail page. |
| Search improvements | A basic client-side keyword and topic-pill filter exists (`content-filters.js`), adequate for the current two-product catalog. |
| Mobile optimization | Already extensively addressed in this project's own prior UI and UX audit history (dark mode, touch targets, responsive layout, accessibility). |
| Email automation | Partially exists: one automated email (the welcome email, Milestone M1) fires on account creation. No other triggered or lifecycle email exists. |

## Genuinely Missing, Evidence-Supported as High Value

| Candidate | Why It Matters, With Evidence |
|---|---|
| Legacy guest-purchase account reconciliation | Fifteen of seventeen verified purchases (88 percent) have no linked customer account, confirmed by direct production query. Not in the sprint brief's own example list; surfaced by this review's own evidence-gathering. |
| Visitor and marketing analytics | Confirmed absent by direct code inspection. Named as an unresolved gap in this project's own prior governance documents (Milestone M4B) at least twice already. |
| Triggered post-purchase review-request email | Confirmed absent (no scheduled trigger of any kind exists in `wrangler.jsonc`). Directly closes a gap Milestone M4B's own Customer Journey Validation predicted in advance and this review's production data now confirms as a real, measured zero (0 reviews ever submitted). |

## Genuinely Missing, Not Currently Justified by Evidence

| Candidate | Why It Is Not Recommended Now |
|---|---|
| Wishlist | No evidence of demand; with a two-product catalog (one of them not yet purchasable), a wishlist has almost nothing to hold. |
| Gift purchases | No evidence of demand; would add checkout complexity for a feature with no observed request behind it. |
| Customer profiles (beyond the existing account security page) | The existing account page already covers email and password; a richer profile (preferences, avatar, saved details) has no clear use case yet at this catalog size. |
| Reading progress | Products are downloadable PDFs, not an in-browser reader. Building reading-progress tracking would require building an entire e-reader first, disproportionate to the current one-book catalog. |
| Recommendations (personalized, beyond the existing related-products feature) | A personalization engine needs meaningfully more purchase and browsing data than 17 lifetime purchases provide to produce results better than the existing topic and type-based related products. |
| Affiliate program | Marketplace-adjacent; no evidence of demand from any real partner, and the platform's own single-seller architecture has no revenue-split mechanism to support payouts yet. |
| Loyalty system | Needs a repeat-purchase base to be meaningful; not observed in production (no evidence either existing account holder has purchased twice). |
| Course platform | Explicitly and repeatedly evaluated and deferred by this project's own governance history (Milestone M4A, Milestone M4B), citing zero course-demand signal in any real customer-submitted content. This review's own data (0 contact messages, 1 consultation request, its topic unknown to this review) does not surface new evidence to revisit that conclusion. |

## Assessed Separately (Mandatory Phase 3)

| Candidate | Verdict |
|---|---|
| Platform Fee Engine | Not recommended for M5 or M6. See `v3.3-platform-fee-engine-assessment.md` for the full, independent assessment; the short reason is that this platform has no marketplace and no second-party seller for a platform fee to apply against. |

## New Candidate Surfaced by This Review, Not in the Brief's Example List

**Activation of the existing coupon and newsletter systems through a first real promotional campaign.** Not a feature to build (both systems already exist and work); a business action recommended to happen regardless of what Version 3.3 itself builds. See `v3.3-revenue-opportunity-report.md`.
