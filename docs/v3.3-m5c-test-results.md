## Regressions found and fixed during this sprint

Two genuine bugs were caught by this new test suite before being considered complete, not shipped and left for a later sprint to discover:

1. **Repeat-purchase same-second tie.** `repeatPurchasesInRange()`'s original query compared only `verified_at`. Two purchases verified within the same second (a real, reachable case at checkout, not a test artifact) produced an equal timestamp, so neither purchase satisfied `prior.verified_at < ps.verified_at` and the pair was silently undercounted as zero repeat purchases instead of one. Fixed by adding `id` as a tiebreaker (`prior.verified_at < ps.verified_at OR (prior.verified_at = ps.verified_at AND prior.id < ps.id)`). Caught by `analyticsActivationSummary.test.ts`'s "counts a second verified purchase by the same customer as a repeat purchase" test.

2. **Test-file cleanup ordering.** `reviewReminderService.test.ts`'s second `describe` block's `beforeEach` deleted `customers` without first deleting `purchase_sessions`/`product_reviews` rows left over from the first `describe` block's tests, causing a foreign-key constraint failure on `DELETE FROM customers`. This was a test-infrastructure bug, not a product bug — fixed by adding the missing cleanup statements to the second block's `beforeEach`, matching the first block's ordering.

## Regression check against pre-existing suite

Before adding the `PASSWORD_NOT_SET` code (previously `INVALID_CREDENTIALS` for the same case), every existing test asserting `error.code === 'INVALID_CREDENTIALS'` was individually re-checked (`tests/integration/rateLimiting.test.ts`, `rateLimitingM3.test.ts`, `negative.test.ts`, `dashboardM3.test.ts`) to confirm none of them exercised the `password_not_set` login path specifically — they test wrong-password, nonexistent-account, oversized-input, and change-password cases, none of which changed. Confirmed by the full suite run: zero pre-existing tests broke.
