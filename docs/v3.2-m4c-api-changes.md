# Version 3.2 - Milestone M4C API Changes

All new endpoints follow this codebase's standard envelope: `{ success: true, data }` or `{ success: false, error: { code, message } }`. All are wired in `backend/worker/index.ts`'s `ROUTES` array; all mutating endpoints are rate-limited via the existing `isRateLimited()` middleware.

---

## Reviews

### `GET /api/products/:slug/reviews`
Public, unauthenticated. Rate limit: `public-reviews-read`, 120/15min.

**Response `data`:**
```json
{ "reviews": [{ "id": 1, "rating": 5, "body": "Great guide.", "createdAt": "2026-07-01 10:00:00" }], "averageRating": 4.7, "count": 12 }
```
Approved reviews only. No customer identity in the response, ever.

### `GET /api/customer/reviews`
Auth: `requireCustomerAuth`. Rate limit: `customer-reviews-read`, 60/15min.

**Response `data`:** `{ "reviews": [{ id, productSlug, productTitle, rating, body, status, createdAt, updatedAt }] }` - the authenticated customer's own reviews, any status, across every product.

### `POST /api/customer/reviews`
Auth: `requireCustomerAuth` + `requireCustomerCsrf` (`X-Customer-CSRF-Token` header). Rate limit: `customer-reviews-write`, 20/15min.

**Request body:** `{ "productSlug": "starting-to-invest-with-gh100", "rating": 5, "body": "Genuinely useful." }`

**Response `data`:** `{ "reviewId": 42, "status": "pending" }` (201)

**Error codes:** `VALIDATION_ERROR` (missing/malformed fields), `PRODUCT_NOT_FOUND`, `NO_VERIFIED_PURCHASE` (403 - "We couldn't find a completed purchase of this product on your account.")

Submitting again for the same product updates the existing review in place (same `reviewId`) and resets its status to `pending`.

### `GET /api/admin/reviews`
Auth: `requireAuth` (any admin role). Rate limit: `admin-ops-read`, 120/15min.

**Query params:** `status` (`pending`/`approved`/`rejected`, optional), `page`, `pageSize` (max 100).

**Response `data`:** `{ "items": [{ id, productSlug, productTitle, customerEmail, rating, body, status, createdAt }], "total": 12, "page": 1, "pageSize": 20 }`

### `POST /api/admin/reviews/:id/moderate`
Auth: `requireAuth` + `requireRole(EDITOR_ROLES)` + `requireCsrf` (`X-CSRF-Token` header). Rate limit: `admin-ops-write`, 60/15min.

**Request body:** `{ "status": "approved" }` or `{ "status": "rejected" }`

**Response `data`:** `{ "moderated": true }`

**Error codes:** `VALIDATION_ERROR` (status not `approved`/`rejected`), `NOT_FOUND`, `FORBIDDEN` (non-editor role or missing CSRF)

## Coupons

### `POST /api/coupons/validate`
Public, unauthenticated, non-mutating. Rate limit: `coupon-validate`, 30/60s.

**Request body:** `{ "productId": "starting-to-invest-with-gh100", "couponCode": "SAVE10" }`

**Response `data` (valid):** `{ "valid": true, "discountPesewas": 390, "finalAmountPesewas": 3510 }`

**Response `data` (invalid):** `{ "valid": false, "reason": "not_found" | "inactive" | "not_started" | "expired" | "product_mismatch" | "redemption_limit_reached" }` - still a `success: true` response; an invalid coupon code is not an error condition, it's a normal outcome this endpoint exists to report.

Never mutates `redemptions_count`. Case-insensitive (codes are stored and matched uppercase).

### `GET /api/admin/coupons`
Auth: `requireAuth` (any admin role). Rate limit: `admin-ops-read`, 120/15min.

**Query params:** `page`, `pageSize` (max 100).

**Response `data`:** `{ "items": [{ id, code, productSlug, discountType, discountValue, maxRedemptions, redemptionsCount, firstPurchaseOnly, startsAt, expiresAt, status, createdAt }], "total": 4, "page": 1, "pageSize": 20 }` - `productSlug` is `null` for a platform-wide coupon.

### `POST /api/admin/coupons`
Auth: `requireAuth` + `requireRole(EDITOR_ROLES)` + `requireCsrf`. Rate limit: `admin-ops-write`, 60/15min.

**Request body:**
```json
{
  "code": "LAUNCH20",
  "productSlug": null,
  "discountType": "percentage",
  "discountValue": 20,
  "maxRedemptions": 100,
  "firstPurchaseOnly": false,
  "startsAt": null,
  "expiresAt": null
}
```

**Response `data`:** `{ "id": 7 }` (201)

**Error codes:** `VALIDATION_ERROR` (invalid code format `/^[A-Z0-9_-]{3,32}$/`, non-positive-integer discount value, percentage over 100, invalid `maxRedemptions`, or a duplicate code), `PRODUCT_NOT_FOUND` (unknown `productSlug`), `FORBIDDEN`

Code is normalized to uppercase before storage. Writes an audit log entry (`coupon.created`).

### `PATCH /api/admin/coupons/:id`
Auth: `requireAuth` + `requireRole(EDITOR_ROLES)` + `requireCsrf`. Rate limit: `admin-ops-write`, 60/15min.

**Request body (any subset):** `{ "status": "disabled", "maxRedemptions": 50, "expiresAt": "2026-12-31T23:59:59.000Z" }`

**Response `data`:** `{ "updated": true }`

**Error codes:** `VALIDATION_ERROR`, `NOT_FOUND`, `FORBIDDEN`

Only `status`, `maxRedemptions`, and `expiresAt` are ever read from the body - `code`, `discountType`, `discountValue`, and `productSlug` are not part of this endpoint's schema at all, immutable after creation by design. Writes an audit log entry (`coupon.updated`).

## Extended Endpoint: `POST /api/checkout/sessions`

**New optional field:** `couponCode: string | null`. Everything else about this endpoint - `productId`, `termsAccepted`, `licenseAccepted`, `marketingOptIn`, the response shape, every existing error code - is unchanged.

**New error code:** `COUPON_INVALID` (400) - returned when a `couponCode` was supplied but failed `validateCoupon()`'s check (the visitor's own, honest error message from `CommerceError`, e.g. "This coupon has expired.").

**Effect on `purchase_sessions`:** when a valid coupon is supplied, `amount_pesewas` reflects the discounted price (not the catalog price), and `coupon_id`/`discount_pesewas` are populated. When no coupon is supplied, both remain `NULL`/`0` and every other field is byte-for-byte identical to pre-M4 behavior.

## Updated `ApiErrorCode` Union

Added to `backend/types/api-contracts.ts`: `'NO_VERIFIED_PURCHASE' | 'COUPON_INVALID'`. Both are mapped in `backend/utils/responses.ts`'s `ERROR_STATUS`: `NO_VERIFIED_PURCHASE: 403`, `COUPON_INVALID: 400`.
