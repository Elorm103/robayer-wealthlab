## Cleanup procedure

Executed in strict dependency order (children before parents, matching the exact FK-safe order established during this same milestone's own local-dev cleanup passes):

```sql
DELETE FROM download_tokens WHERE delivery_id IN (...);
DELETE FROM receipt_download_tokens WHERE receipt_id IN (...);
DELETE FROM deliveries WHERE purchase_session_id IN (...);
DELETE FROM receipts WHERE purchase_session_id IN (...);
DELETE FROM licenses WHERE purchase_session_id IN (...);
DELETE FROM order_items WHERE purchase_session_id IN (...);
DELETE FROM purchase_sessions WHERE purchase_reference='RWL-2026-900099';
DELETE FROM customer_sessions WHERE customer_id IN (...);
DELETE FROM customer_password_tokens WHERE customer_id IN (...);
DELETE FROM customer_profiles WHERE customer_id IN (...);
DELETE FROM customers WHERE email='m3e-verify@robayer-internal-test.example';
DELETE FROM product_files WHERE product_id IN (...);
DELETE FROM media_assets WHERE filename='m3e-verify.pdf';
DELETE FROM products WHERE slug='m3e-verify-product';
```

Executed against production D1 via `wrangler d1 execute robayer-wealthlab-db --remote --file ...`. Result: **19 changes, 18 rows written** across the single batch - matching the expected row count from the table above (1+1+1+1+1+2+1+1+1+1+1+1 = 14 direct deletes, plus a small number of already-consumed token rows cascaded in).

The R2 placeholder object was separately removed via `wrangler r2 object delete robayer-wealthlab-storage/ebooks/m3e-verify.pdf --remote`.
